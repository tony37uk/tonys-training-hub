Getting Started with Google Antigravity

⏱️ 20–25 minutes 🟡 Intermediate 🖥️ App · IDE · CLI · editor extensions 🗓️ Updated November 2026

Google Antigravity is Google's "agent-first" development platform. Instead of an editor with an AI chat bolted on, it puts AI agents at the centre: you describe a task, the agent plans it, writes the code, runs it, tests it in a browser and shows you evidence of what it did. It's also where Google now sends anyone who used the free Gemini CLI.

💡

In one sentence: Antigravity is a mission control for AI coding agents — you hand out tasks, review their plans and results, and approve the risky steps.

🪐 What is Antigravity?

Antigravity launched in late 2025 and was relaunched as Antigravity 2.0 at Google I/O in May 2026. It's now a family of tools that share one agent, one account and one set of settings. Pick the one that matches how you like to work:

Key ideaWhat it means for you

ArtifactsInstead of a wall of logs, the agent produces things you can check: a plan, a task list, a walkthrough of what it changed, screenshots and browser recordings.

🖥️ Set up the Antigravity App

1

Install and sign in

  1. Download the installer for your system from antigravity.google/download. On a Mac, drag Antigravity into Applications; on Windows, run the installer.
  2. Open Antigravity and click Sign in. Complete the sign-in in your browser with your Google account.
  3. Choose a role — Software Engineering for coding, or Knowledge Work for documents and research — and accept the terms.
2

Create a project and run your first task

  1. Click the New Project icon in the left sidebar, then Add Folder and choose your project folder. Click Create.
  2. Type a task in the prompt box and press Enter — for example, "Add a dark mode toggle to this website".
  3. Choose a mode: Local mode works directly in your folder; New worktree mode works in a separate, isolated copy of your Git project.
  4. Review the plan the agent produces, approve it, then check the walkthrough and screenshots when it's done.
💡

Choose New worktree mode while you're learning. The agent's changes stay in their own copy until you decide to keep them, so your main project is never touched by surprise. It also lets you run several agents side by side without them getting in each other's way.

⌨️ Set up the Antigravity CLI 

# macOS and Linux
curl -fsSL https://antigravity.google/cli/install.sh | bash

# Windows (PowerShell)
irm https://antigravity.google/cli/install.ps1 | iex

# Check it worked (reopen your terminal if the command isn't found)
agy --version

# Start it inside your project folder
cd my-project
agy

On first run, agy opens your browser to sign in with your Google account, then asks you to confirm that you trust the folder. Describe a task, and press Y to approve each change it wants to make.

CommandWhat it does
/planSwitch to plan mode: the agent writes an implementation plan before changing anything
/modelChoose which model to use
/diffSee exactly what's changed
Ctrl + RReview the agent's artifacts (plans, walkthroughs)
agy -p "…"Run a single task without the interactive session
/exitQuit
🔁

Coming from Gemini CLI? On 18 June 2026, Gemini CLI stopped working for free and Google AI Pro/Ultra sign-ins. Google's replacement is Antigravity CLI, which supports agent skills, hooks, subagents and extensions, and the docs include a Gemini migration guide. Gemini CLI itself still works if you use it with a paid Gemini API key.

🧩 Use it inside your own editor

If you'd rather stay in VS Code (1.90 or later), open the Extensions sidebar, search for Google Antigravity and click Install. Then open the Antigravity agent panel and sign in with the same Google account. Extensions are also available for JetBrains IDEs, Visual Studio, Zed, Xcode and Eclipse, and work on the free plan too.

🛡️ Permissions and safety

Antigravity's agent can run commands, read files and use a browser, so its permission settings matter. Each project has a Permission Preset:

PresetTerminal commandsFile accessMCP & webUse it when…
Request ReviewAlways asksProject onlyAsksLearning, or real work data
DefaultRuns in a sandbox; asks outside itProject + temp foldersAsksEveryday work
AutoSandbox; outside it, checked automaticallyProject + temp foldersAsksTrusted projects
TurboRuns anythingWhole computerAllowedThrowaway test machines only
!

Safety checklist

  • → Stay on Default or Request Review, and avoid Turbo on any computer holding your work accounts or credentials.
  • → Use New worktree mode so changes stay isolated until you keep them.
  • → Keep secrets such as API keys out of the project folder, or in files the agent is told not to read.
  • → Limit which websites the browser agent can visit using the browser allow and deny lists, especially on work projects.
  • → Read the plan before approving it, and read any command before you let it run.
⚠️

Prompt injection is a real risk here. Security researchers showed early on that hidden instructions in files or web pages could trick Antigravity's agent into running commands when its settings were too relaxed. Tighter permissions are your best defence — see AI Security Basics for how these attacks work.

✅ Best practices

1

Plan first, and actually review the plan

For anything beyond a small fix, ask for a plan (/plan in the CLI). The agent produces an implementation plan as an artifact: read it, comment on it, and only then let it build. Fixing a plan is far cheaper than fixing code.

2

Check the evidence, not just the summary

When a task finishes, open the walkthrough, screenshots and browser recordings. They show what the agent actually did and tested — far more reliable than "Done! Everything works."

3

Teach it your project once

Use Rules to set standing instructions (tech stack, style, what never to touch) and Workflows for tasks you repeat, like "run tests and fix failures". Skills, MCP servers and plugins add extra abilities — install only ones you trust.

4

Small tasks, run in parallel

Give each agent one focused task rather than one agent a huge job. With worktree mode you can run several at once — say, one writing tests while another fixes a bug — and approve their requests from the Inbox.

5

Keep Git as your safety net

Commit before each task, review changes with /diff or the editor's diff view, and keep only what you're happy with. If something goes wrong, you can always roll back.
